# mongdock "문제 신고하기" 받는 창구 (Google Apps Script)

몽독 앱의 "문제 신고하기…"가 보낸 내용을 받아 지원 주소 `mongdock+help@gmail.com` 으로 메일을 만든다. 사용자는 메일 계정이 없어도 신고할 수 있고, 모든 신고는 지원 메일함 한 곳(→ `tools/support-mail-mcp`)으로 모인다.

## 배포 (mongdock@gmail.com 으로 한 번)
1. https://script.google.com 에 `mongdock@gmail.com` 으로 로그인 → **새 프로젝트**. 이름: `mongdock-report`.
2. 기본 `Code.gs` 내용을 지우고 이 폴더의 `Code.gs` 를 통째로 붙여 넣기 → 저장(Ctrl+S).
3. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱** 선택.
   - 설명: `v1`
   - 다음 사용자 인증 정보로 실행: **나 (mongdock@gmail.com)**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** → 권한 확인 창에서 mongdock 계정 선택 → "확인되지 않은 앱" 이 나오면 **고급 → mongdock-report(으)로 이동** → **허용** (자기 계정의 메일 보내기 권한).
5. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 PM 세션에 알려 준다 → 앱 설정에 들어감.

코드를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포** 로 같은 URL 을 유지한다.

## 동작
- 앱이 보내는 JSON: `token`, `clientId`(PC별 무작위), `kind`(bug/question/idea), `message`, `contact`(선택), `appVersion`, `lang`, `diagnostics`(앱이 개인정보를 가린 뒤).
- 하루 한도: PC 당 5건, 전체 80건(Gmail 일반 계정 Apps Script 발송 한도 100통 안쪽). 넘으면 429.
- 답장 주소를 적은 신고만 `Reply-To` 가 붙어서, 지원 MCP 의 형식 답장이 그 사람에게 간다. 안 적었으면 답장하지 않는다(지원 MCP 가 자기 주소로는 답장을 거부).
- `token` 은 비밀이 아니다(앱에 들어 있음). 아무나 막 보내는 걸 조금 거르는 용도이고, 실제 보호는 하루 한도다.

## 사용 통계 (#20)

같은 웹 앱이 `{"type":"stats"}` 요청도 받는다. 메일을 만들지 않고 **구글 시트 `mongdock-stats`** 에 하루치마다 한 줄씩 쌓는다(시트는 첫 신호 때 스크립트가 mongdock 계정 드라이브에 만든다).

- 앱이 보내는 것 (하루 한 번, 오프라인이면 최대 7일치를 한꺼번에): 날짜, 앱 버전, 설치 방식(store/installer/zip), 윈도우 10/11·빌드, 언어(ko/en), 노트북 여부, 모니터 수, 주 모니터 배율, 독 자동 숨김·상단바·알림 표시 방식·캘린더 연결 있음·검색 버튼·작업 표시줄 숨기기·가벼운 모드, 지난 신호 이후 오류 수.
- PC 번호·이름·IP 는 없다. 하루치마다 무작위 `nonce` 가 붙는데(재전송 중복 거르기용, 6시간 기억, 시트에는 안 남김) 날짜·PC 를 잇지 않는다. 스크립트는 위 칸만 검사해서 남기고 그 밖의 값은 버린다(`STATS_COLUMNS`). 하루 전체 2만 줄 상한.
- 앱 쪽: `src/mongdock/Services/UsageStatsService.cs`, 설정 → 정보 → "사용 통계 보내기" 로 끔. 시험할 때는 환경 변수 `MONGDOCK_STATS=log` (보내지 않고 로그에만).

### 재배포 순서 (mongdock@gmail.com, 한 번)
1. https://script.google.com 에서 `mongdock-report` 프로젝트를 열고 `Code.gs` 를 이 폴더의 것으로 통째로 바꿔 저장.
2. 편집기 위 함수 목록에서 `statsSheet_` 를 고르고 **실행** → 권한 확인 창에서 **스프레드시트 보기·만들기** 권한 허용 (새 권한이라 한 번 필요). 드라이브에 `mongdock-stats` 시트가 생기면 성공.
3. **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**. URL 이 그대로라 앱은 바꿀 것 없음.
   - 재배포 전에 온 신호는 옛 스크립트가 400 으로 돌려보내고, 앱이 모아 두었다가(최대 7일) 다음에 다시 보낸다.

### 대시보드 (본인만)
- 주소: 웹 앱 URL 뒤에 `?view=stats` (예 `https://script.google.com/macros/s/.../exec?view=stats`).
- 웹 앱은 "실행 = 나" 라서, 이 주소를 연 사람이 **스크립트 소유자(mongdock@gmail.com)일 때만** 구글이 이메일을 알려 준다. 다른 계정·로그아웃 상태는 빈 값 → "권한 없음".
- 확인 방법: ① mongdock 계정으로 로그인한 브라우저에서 열면 표가 보임. ② 시크릿 창(로그인 안 함)과 다른 구글 계정으로 열면 "권한 없음". 둘 다 확인.
- 크롬에 구글 계정이 여러 개 로그인돼 있으면 기본 계정으로 열려 "권한 없음" 이 나올 수 있다 → mongdock 계정만 로그인한 프로필에서 열기.
- 보이는 것: 날짜별 신호 수(최근 30일), 최근 7일의 버전·설치 방식·윈도우·언어·모니터·배율·알림 표시 분포, 기능 켜짐 비율, 오류 합계. 원본은 맨 아래 "시트 열기".
